# בלי פאדיחות · Birthly

בוט טלגרם לניהול ימי הולדת ותאריכים חוזרים, עם תמיכה מלאה בלוח העברי ובלוח הלועזי.
מוסיפים אדם בשלושה צעדים, והבוט שולח תזכורת בזמן — פעם אחת, בשעה שבחרתם.

> **סטטוס:** אפיון מאושר, הפיתוח טרם התחיל.
> **המסמך המחייב:** [SPEC.md](SPEC.md) — כל מה שצריך לבנות נמצא שם.

---

## למי שמפתח את הפרויקט (אדם או סוכן AI)

**קרא את [SPEC.md](SPEC.md) במלואו לפני שאתה כותב שורת קוד.** הוא ה‑Source of Truth היחיד:
מבנה קבצים, סכימת DB, כל מסך, כל כפתור, כל callback ID, וכל כלל התנהגות.

אם משהו נראה חסר — הוא כנראה לא. בדוק בפרק 36 (שאלות פתוחות), שם רשומה **ברירת מחדל מחייבת** לכל מקרה שלא הוכרע. אל תמציא.

### סדר הבנייה

עקוב אחרי ה‑Milestones בפרק 35. שני דברים שאסור לדלג עליהם:

- **M2 קודם לממשק.** `app/core/` (חישובי תאריכים, לוח עברי, פורמטים, ולידציה) נבנה ומכוסה ב‑100% טסטים **לפני** שנוגעים במסכים. זה המקום היחיד בפרויקט שבו באג שקט עולה ביוקר — תזכורת שיוצאת ביום הלא נכון.
- **המנוע בפרק 18.** ה‑`UNIQUE(event_id, rule_id, occurrence_date)` וה‑grace window הם מה שמבטיח "בדיוק פעם אחת". אל תפשט אותם.

### הכלל שגובר על הכל

[פרק 11.1 — חוזה הפשטות](SPEC.md#111-חוזה-הפשטות--הכלל-שגובר-על-הכל). בקצרה:

> **רק שם ותאריך הם חובה.** הוספת אירוע = 2 מסכים. הוספת תזכורת = לחיצה אחת.
> לכל שאלה אחרת יש `דלג ←`, והדילוג לא עולה למשתמש בכלום — בלי אזהרות, בלי progress bar, בלי "חסרים לך פרטים".

זו הדרישה שהכי קל להפר בלי לשים לב: עוד שאלה קטנה, עוד מסך אישור, עוד שדה שנראה הגיוני לבקש. אם זרימה גדלה מעבר למספרים האלה — משהו הפך לחובה שלא היה צריך.

## הסטאק

Python 3.12 · aiogram 3 · SQLAlchemy 2.0 (async) · SQLite · Alembic · APScheduler · pyluach

פריסה: systemd + venv על Ubuntu. **אין Docker, אין Redis, אין Celery** — ולא צריך.

---

## התקנה מקומית (פיתוח)

```bash
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt

cp .env.example .env               # הכנס BOT_TOKEN ו‑ADMIN_IDS
alembic upgrade head
python -m app.main
```

## התקנה על שרת

```bash
git clone <repo> /opt/birthly && cd /opt/birthly
bash deploy/install.sh
```
פרטים מלאים: [SPEC.md · פרק 33](SPEC.md#33-deployment)

## פקודות שימושיות

```bash
make run        # הרצה מקומית
make test       # pytest + coverage
make lint       # ruff + mypy
make migrate    # alembic upgrade head
make backup     # גיבוי ידני של ה‑DB
```

## מבנה הפרויקט

| תיקייה | תפקיד |
|--------|-------|
| `app/core/` | פונקציות טהורות — תאריכים, לוח עברי, פורמטים, ולידציה. בלי DB, בלי I/O. |
| `app/db/` | מודלים + repositories. **כל שאילתה מסוננת ב‑`user_id`.** |
| `app/services/` | כל הלוגיקה העסקית. לא מכיר את aiogram. |
| `app/handlers/` | ניתוב ורינדור בלבד. אסור SQL, אסור לוגיקה. |
| `app/scheduler/` | ה‑jobs, כולל מנוע התזכורות. |
| `locales/` | **כל** מחרוזת בממשק. אפס טקסט עברי בקוד. |

הפרדת השכבות היא לא המלצה — היא נאכפת. פירוט: [SPEC.md · פרק 5](SPEC.md#5-architecture)
